# 🛠️ Detailed Contribution Guide

Thank you for your interest in contributing to the Dev Resource Hub! This guide provides more technical details on how to contribute effectively.

## 📁 Repository Structure
- `categories/`: Contains the actual resource lists separated by domain.
- `docs/`: Documentation and project guides.
- `.github/`: Issue templates and PR templates.
- `assets/`: Images and branding materials.
- `examples/`: Examples of how to format new additions.

## 📝 Formatting Standards
When adding a resource, please use the following Markdown format:
```md
- **Tool Name** – Short description (keep it under 100 characters)
  🔗 [https://example.com](https://example.com)
```

## 🔍 Quality Checklist
Before submitting a PR, please ensure:
1. The resource is not a duplicate.
2. The link is working and goes to the official site.
3. The description is accurate and objective.
4. You've added it to the correct category file.

## 🚀 Submission Process
1. Fork the repo.
2. Create a feature branch (`git checkout -b add-resource-name`).
3. Commit your changes with a clear message (`git commit -m "Add Resource Name to Category"`).
4. Push to your fork and open a PR.
